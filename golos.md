# Голосовой пульт для компьютера и VPS через Codex

Эта инструкция помогает собрать личную систему управления: вы говорите с **Codex на компьютере**, Codex выполняет разрешённые действия на компьютере и по SSH обращается к вашему VPS. Телефон подключается к работающему компьютеру через **Remote** в приложении ChatGPT. Отдельный голосовой сервер для такого старта не нужен.

> Схема: **голос → Codex на компьютере → локальные инструменты / SSH → VPS**. Телефон — дополнительный пульт к тому же компьютеру, а не самостоятельный сервер.

Пример рассчитан на Mac и VPS с Linux. Интерфейс Codex есть и на Windows, но команды установки SSH-ключа и названия системных настроек там будут другими. Возможности Voice и Remote зависят от вашего аккаунта, региона, версии приложения и настроек рабочего пространства.

## 1. Что понадобится

- Компьютер с актуальным приложением ChatGPT/Codex и входом в свой аккаунт.
- VPS с доступом по SSH и отдельным пользователем, например `operator`. Не используйте `root` для повседневных голосовых команд.
- Приложение ChatGPT на телефоне с тем же аккаунтом и рабочим пространством.
- Для голосового разговора на компьютере — микрофон и разрешение macOS на его использование.

Ниже `example.com`, `operator`, `my-vps` и имена служб — **только примеры**. Подставляйте свои значения у себя на устройстве. Не публикуйте настоящие адреса, ключи, токены, конфиги SSH и скриншоты с кодом сопряжения.

## 2. Проверьте вход на VPS с компьютера

Сначала добейтесь обычного SSH-доступа без участия ИИ. На Mac откройте Терминал:

```bash
ssh operator@example.com 'hostname; uptime'
```

Если вход работает, создайте отдельный ключ для этого доступа, если подходящего ключа ещё нет:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_codex
```

Добавьте **публичную** часть ключа (`~/.ssh/id_ed25519_codex.pub`) в настройках SSH-ключей вашего VPS-провайдера или в `~/.ssh/authorized_keys` пользователя на сервере. Приватный файл `~/.ssh/id_ed25519_codex` никуда не отправляйте и не вставляйте в чат. Если провайдер уже настроил вход по ключу, этот шаг можно пропустить.

Чтобы не диктовать адрес сервера, добавьте у себя на компьютере запись в `~/.ssh/config`:

```sshconfig
Host my-vps
    HostName example.com
    User operator
    IdentityFile ~/.ssh/id_ed25519_codex
    IdentitiesOnly yes
```

Проверьте именно новую короткую команду:

```bash
ssh my-vps 'hostname; uptime'
```

При первом подключении SSH попросит сверить отпечаток сервера. Сверьте его с данными провайдера до подтверждения. Пароль и одноразовые коды вводите сами в Терминале, не сообщайте их агенту.

## 3. Дайте Codex понятные границы

В приложении откройте **Codex**, выберите папку проекта на компьютере и создайте чат. Начните с проверочной просьбы:

> Проверь на Маке текущую папку и статус Git. Затем на сервере выполни только `ssh my-vps 'hostname; uptime'`. Перед любыми изменениями объясни, что собираешься сделать.

Если доступ к Терминалу требует разрешения, одобрите конкретную команду в интерфейсе. Для начала не выдавайте широких постоянных разрешений: сначала посмотрите, какие команды агент предлагает и какие данные видит.

Для постоянных правил в рабочей папке можно создать `AGENTS.md`:

```markdown
# Правила моего агента

- Перед действием коротко объясняй цель.
- Различай компьютер и VPS; в отчёте называй место действия.
- На VPS сначала читай состояние. Перед изменением файлов, служб,
  расписаний и баз запрашивай моё явное согласие.
- Перед удалением, публикацией или отправкой сообщения другим людям
  показывай точную цель и жди подтверждения.
- Не печатай значения секретов из .env, SSH, менеджера паролей и токенов.
- После действия показывай проверку: команду и короткий результат.
```

Это инструкция агенту, а **не техническая защита** от опасной команды. Права пользователя на сервере, SSH-настройки и запросы разрешения в Codex остаются отдельными рубежами. Проверяйте предлагаемую команду перед одобрением.

## 4. Включите голос на компьютере

В приложении ChatGPT на компьютере перейдите именно в **Codex**, откройте нужный чат и нажмите кнопку **Voice**. Разрешите микрофон. При управлении экраном могут понадобиться отдельные разрешения macOS на запись экрана и Accessibility — выдавайте их только для тех задач, где они нужны.

Проверка голосом:

> Посмотри, доступен ли мой VPS. Только чтение. Назови команду и результат.

Затем попробуйте задачу с несколькими шагами:

> Проверь состояние моего проекта на компьютере и свободное место на VPS. Ничего не меняй. Скажи, где именно нашёл каждый результат.

Voice использует инструменты и разрешения **выбранного режима**. Обычный голосовой чат ChatGPT и голос в Codex — разные рабочие контексты. Если Codex не видит проект или не предлагает терминальные действия, проверьте, что выбран Codex и нужная папка.

## 5. Подключите телефон

На компьютере откройте **Settings → Connections → Control this Mac or PC → Set up / Add** и покажите QR-код. В приложении ChatGPT на телефоне откройте **Remote** и отсканируйте код. Войдите в тот же аккаунт и рабочее пространство. Названия пунктов могут немного меняться после обновлений.

После сопряжения выберите компьютер в Remote, откройте тот же чат Codex и попросите выполнить безопасную проверку VPS. Компьютер должен оставаться включённым, подключённым к сети и с работающим Codex. Именно он выполняет команды; телефон показывает ход работы и запросы разрешения.

На поддерживаемом **iPhone** голосовой разговор с сопряжённым настольным Codex может быть доступен через Remote. На **Android** сначала проверьте, есть ли Voice именно внутри удалённого чата Codex в вашей версии приложения; доступ к Remote сам по себе не гарантирует этот голосовой режим. Голосовой Work на телефоне — другой режим, и он не получает автоматически доступ к файлам вашего компьютера или к его SSH-сеансу. Если голос в Remote недоступен, отправляйте Codex текст или используйте диктовку телефона как ввод текста.

## 6. Подключайте остальные части системы по одной

Управление «всем» получается из отдельных, проверенных путей доступа. Например:

| Задача | Как подключить | Первая безопасная проверка |
| --- | --- | --- |
| Файлы и код на компьютере | Открыть нужную папку в Codex | Показать `pwd` и `git status` |
| VPS | SSH-ключ и запись `my-vps` | `ssh my-vps 'hostname; uptime'` |
| Службы на VPS | Права пользователя на чтение `systemctl` | `ssh my-vps 'systemctl status example.service --no-pager'` |
| Другие приложения | Подключить соответствующий инструмент или разрешение в Codex | Прочитать один тестовый объект |
| Другие агенты | Дать Codex документированную команду или API для каждого адресата | Прочитать состояние и отправить тест только с вашего согласия |

Для частых действий сделайте короткие **именованные команды** у себя на компьютере: например, отдельную команду для чтения журнала и отдельную для перезапуска конкретной службы. Каждая команда должна проверять допустимое имя и сообщать, что собирается сделать. Не стройте один универсальный скрипт с неограниченным `sudo`.

После подключения каждого нового действия проверьте три вещи: что команда попала на нужную машину, что Codex показал исходные данные и что изменение подтвердилось повторным чтением. Для перезапуска или удаления заранее договоритесь о явном подтверждении в интерфейсе. На телефоне разрешение опасного действия подтверждайте **экранной кнопкой**; устное «да» не заменяет экранное одобрение.

## Если что-то не работает

- **SSH не входит:** проверьте вход той же командой в Терминале, права на ключ и пользователя в `~/.ssh/config`. Не отправляйте приватный ключ в чат для диагностики.
- **На компьютере нет Voice:** обновите приложение, проверьте доступность функции для аккаунта и разрешение микрофона.
- **Телефон не видит компьютер:** проверьте один аккаунт и рабочее пространство, сеть, сон компьютера и настройку Remote. Повторите сопряжение через настройки приложения.
- **На телефоне открылся обычный Chat/Work:** перейдите в **Remote** и выберите чат на подключённом компьютере.
- **Агент предлагает слишком широкую команду:** отклоните её и попросите показать более узкую команду и её последствия.

## Что здесь намеренно отделено

Возможна более сложная архитектура с отдельным голосовым веб-приложением, LiveKit и агентом на VPS. Это самостоятельный проект: ему нужны аудиотранспорт, распознавание речи, синтез голоса, авторизация, деплой и эксплуатация. Для описанного выше управления через **Voice в Codex** он не требуется. Не смешивайте эти схемы, пока базовая цепочка Codex → компьютер → SSH → VPS → телефон не проверена.
